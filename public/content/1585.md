InvokeAI 7.0.0 (alpha 4)
Caution
⚠️  Please read this before you install
If you point v7 at your existing InvokeAI root directory, it will upgrade your database, and that database will no longer work with InvokeAI v6. The migrations only go one way, and v6 refuses to open a database that contains migrations it doesn't recognise.
To try v7, create a brand-new InvokeAI root directory and experiment there. In the  Invoke Launcher , choose a new, empty install location. When prompted for the version, select Manual and enter version v7.0.0-alpha.4. For a manual install, pass --root /path/to/new/folder or set INVOKEAI_ROOT. Keep your v6 install and its root directory exactly where they are.
Upgraded your v6 database by accident? Don't panic. Invoke makes a backup before it migrates anything, and from this release on the startup log names that backup before the upgrade begins. See Restoring your v6 database at the bottom of these notes, or the new Upgrading to v7 guide.
Warning
This is alpha software. Things will break, some features are half-finished, and a few corners still have cobwebs. Please don't trust it with work you can't afford to lose. When you hit a bug, and you will, please open an issue on GitHub and put v7 in the title, or tell us about it on our Discord. Screenshots, logs and the output of the Diagnostics panel all help a lot.
Note
Alpha 4 adds a database migration, so once alpha 4 has opened your root directory, alpha 3 and earlier will refuse to start on it. Canvases that use the new Noise, Clarity, Texture or Dehaze adjustments, or the new type-first control layers, are saved in a newer canvas format that alpha 3 can't open. Please stay on alpha 4 once you upgrade.
What's New
Alpha 4 brings three new image model families, character and edit references for Anima, Krea-2 and Qwen-Image-2.1, new ControlNets, much better live previews, faster int8 models, Windows on ARM64, and the return of more features from the legacy interface. A lot of this release is also the result of your feedback on the earlier alphas, so thank you to everyone who reported bugs.
Major Features
Major new features include:
New model families: FLUX.3 Klein and MOSS-Image
- FLUX.3 Image Klein from Black Forest Labs, in both the step-distilled Klein (16 steps, no CFG) and the undistilled Klein Base. It generates from text and edits or combines up to ten reference images, and Canvas regional guidance is placed as FLUX.3 layout boxes. Both checkpoints are under the FLUX Kommunity License. (@Pfannkuchensack)
- MOSS-Image from OpenMOSS, in Base and SFT versions (Apache 2.0). It works in Generate, on the Canvas (img2img, inpaint, outpaint and regional guidance as layout elements) and in workflows, can decode with PiD, and comes with a prompt enhancer that expands a short prompt into a full caption or a layout draft. (@Pfannkuchensack)
📖 FLUX.3 · MOSS-Image
Reference images and edits
- Anima character references. Anima now supports IP-Adapter character reference images. (@lstein)
- Krea-2 edit mode. Krea-2 can take up to three reference images, in Generate, on the Canvas and in workflows. This is what makes ai-toolkit edit LoRAs (the pose and depth "ControlNets" people have been asking for) actually work. (@Pfannkuchensack)
- Qwen-Image-2.1 edits from reference images, plus LoRA support for Qwen-Image-2.1. (@Pfannkuchensack)
📖 Anima · Krea-2 · Qwen-Image-2.1
New ControlNets and type-first control layers
- FLUX.2 [dev] Fun-ControlNet-Union and the InstantX Qwen-Image ControlNet Union are supported, with Canvas control layers. (@Pfannkuchensack)
- Canvas control layers are now type-first: you say what the image should control (Pose, Depth, Edges, Line art, Sketch, Color, Tile and so on) and Invoke picks the detector and the model, runs detection in the background, and keeps the original beside the detected map so you can re-run it. Gallery images and raster layers get Use as Control. (@joshistoast)
Better live previews with Tiny AutoEncoders
Set tiny_autoencoder_previews: true in invokeai.yaml and install the matching Tiny AutoEncoder from the starter models, and the in-progress preview becomes a close likeness of the final image instead of a blurry approximation. A preview takes about 25 ms on an RTX 4090. The finished image is unchanged. (@Pfannkuchensack)
Faster int8 models, and more single-file and GGUF formats
- int8_compute. A new opt-in setting runs ComfyUI int8 convrot builds on the GPU's int8 tensor cores. On an RTX 4090 the denoising step of Z-Image Turbo, FLUX.1 dev and Krea-2 Turbo runs 1.3–2× faster, and up to almost 4× when the model only partly fits in VRAM. It needs an RTX 30-series or newer NVIDIA GPU and Triton, which is now installed automatically on Windows NVIDIA installs. Images differ slightly from the default at the same seed. (@Pfannkuchensack)
- int8 convrot weights now stay int8 while they stream from system RAM, so partially loaded models move half as much data. (@Pfannkuchensack)
- New fp8 and int8 single-file starter models. (@Pfannkuchensack)
- New formats: Krea-2 ComfyUI int4 convrot transformers, Anima transformer GGUFs, LTX-2.5 transformer GGUFs and the Gemma-4 text encoder as GGUF. GGUF models are also identified much faster, from the file header alone. (@Pfannkuchensack)
- attention_backend can now pin a PyTorch attention kernel (cudnn, flash, efficient or math), which is mostly useful for debugging. (@Pfannkuchensack)
📖 int8 Compute · Model Format Support
Upscaling
- The Upscale widget now works with FLUX.2 and Qwen-Image too. (@Pfannkuchensack)
- A new Model only mode runs an upscaler such as 4x UltraSharp by itself, with no denoise pass, and each image's menu has an Upscale submenu listing your installed upscalers at their native scale. (@joshistoast)
📖 Upscale
Canvas adjustments
- Layers and groups get Noise (film grain, with mono, colour and chroma grain and a midtone response), Clarity, Texture and Dehaze adjustments. (@joshistoast)
- The same Clarity, Texture and Contrast Dehaze are available as workflow nodes. (@JPPhoto)
- Layers can be saved to a board of your choice. (@joshistoast)
📖 Image Detail and Contrast Nodes
Shared workflows
In multi-user mode, you can now make a Library workflow Public so that other users of the same Invoke server can open, duplicate or download it from the Shared tab, and call it from compatible workflow nodes. Only the owner can rename, delete or change it. (@JPPhoto)
Windows on ARM64
Invoke now installs and runs natively on Windows on ARM64, including NVIDIA's RTX Spark developer preview, using NVIDIA's ARM64 build of PyTorch. As part of this work, password hashing in multi-user mode now uses bcrypt directly instead of passlib. (@lstein)
Working memory that fits the model
Invoke now reserves working memory for FLUX.2, FLUX.3, Z-Image and Krea-2 denoising, and for VAE decoding, from measurements of each model rather than from rough estimates. That means fewer out-of-memory errors without holding back more VRAM than needed. Administrators can also calibrate a model's VAE working memory from the Model Manager. (@Pfannkuchensack)
More old favourites, and lots of polish from your feedback
- Hosted-provider options, Canvas modes and model record editing are back from the legacy interface, as are PBR map generation and image storage administration in the Gallery. (@joshistoast)
- Undo instead of confirm. Moves, removals, archives, stars, preset changes and layout resets happen straight away and offer Undo. Only permanent or bulk actions still ask first. The Invoke button opens a card that shows the source, the destination and anything blocking the run, along with its fix. The Queue gets a Cache popover for the model and invocation caches. (@joshistoast)
- Gallery and viewer: an Auto-switch menu (Newest / In progress / Off), previous and next arrows, search across All boards, and bulk delete for wildcards. Shift+click Invoke queues at the front. (@joshistoast)
- Workflow editor: fixes for paste, board pickers, library sorting and templates. (@joshistoast)
- External clients that enqueue with destination: "gallery:reveal" can now reveal videos as well as images. (@lstein)
- Many more Canvas fixes for frames, layer actions and the canvas engine. (@joshistoast)

What's New
Alpha 3 brings board sharing, a new image model, a faster attention backend for NVIDIA cards, and the return of a long list of features from the legacy interface. As usual, there's also a big pile of bug fixes.
Major Features
Major new features include:
Board sharing by role
Boards can now be shared with specific roles. Each board has an owner, and everyone else gets one of four roles on it: Viewer, Contributor, Editor or Owner. A board's general access can be Restricted, Everyone can view or Everyone can contribute. Boards that other people share with you show up under Shared with me in the Gallery's board list, along with who owns them and what you can do there, and board menus only offer the actions your role allows. Administrators also get an Other users' boards section.
Projects now keep each member's own settings (layout, widgets, generation settings, prompt history, selection and staging) separate from the project's shared content. When you export a project as an .invk file you can choose whether to Include my settings for this project. This is the groundwork for the project collaboration features coming later in 7.X. (@joshistoast)
See the Multi-User Mode user guide for details.
Qwen-Image-2.1
We now support Qwen-Image-2.1, both the Base model and the 8-step Turbo, for text-to-image and for canvas img2img, inpaint and outpaint. It loads as Diffusers folders, single-file transformers (bf16, ComfyUI scaled fp8 or int8_convrot) and GGUF transformers. You'll find the Base and Turbo models, a Q4_K_M GGUF and the ComfyUI VAE in the starter models. (@Pfannkuchensack)
SageAttention for faster generation on NVIDIA GPUs
There's a new opt-in setting in invokeai.yaml, attention_backend: sage. It runs the attention inside the diffusion model on SageAttention 2.2, an 8-bit attention kernel. It works with FLUX.1, FLUX.2, Z-Image, Qwen-Image, Krea-2, SDXL, LTX-2 and Wan 2.2. The speedup is modest at 1024², but on an RTX 4090 under Windows whole generations run 15–35% faster at 2048², and video gets 12–35% faster. Because the kernel is quantised, images won't be pixel-identical to the default backend at the same seed. SageAttention is installed separately and needs an RTX 30-series or newer NVIDIA GPU. (@Pfannkuchensack)
More models in the Upscale widget
The Upscale widget now works with Z-Image, Anima and Krea-2 (Turbo and Raw), in addition to SD1.5, SDXL and FLUX.1. The Creativity setting has been recalibrated so that it changes the image about the same amount whichever model you pick. The FLUX.2 VAE encode and decode nodes can now tile too, which lets FLUX.2 handle large images on most cards. (@Pfannkuchensack)
📖 Upscale
Old favourites are back
We went through the legacy interface carefully and brought back the features that hadn't made it into the new one yet (@joshistoast):
- SDXL Refiner in Generate and Canvas, including recall of the refiner settings.
- Model-family tuning controls: FLUX.1 DyPE, Z-Image shift override and seed-variance enhancer, Qwen-Image shift override and text-encoder quantisation, and a Krea-2 style reference image with its own strength slider.
- NSFW checker and invisible watermark as per-project settings (off by default).
- PiD decoding on Canvas, plus an optional Anima inpaint/outpaint adapter.
- Canvas: eraser width follows pen pressure, Alt+[ / Alt+] cycle through layers, Q jumps to a bookmarked layer, and the reference-image crop tool has aspect-ratio presets, zoom, pan and Save to Uploads.
- Queue: failed and canceled items can be retried, and their results go where the original run was headed.
- Recall and gallery: Recall All restores more of the legacy settings, and middle-click can open media in a new browser tab (opt-in). Load Workflow now works on any generated image, not just ones that carry an authored workflow.
Gallery improvements
- Filter by media type. The Gallery and the Image Map both have a new Both / Images only / Videos only filter. (@lstein)
- Live updates from other programs. Images generated by external clients that use the REST API, such as chatbots and scripts, now appear in the gallery straight away. A client can also ask for its result to be revealed and selected by enqueuing with destination: "gallery:reveal". (@lstein)
