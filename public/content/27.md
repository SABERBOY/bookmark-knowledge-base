Preface.
As the game grow and reach out for more audiences, Localization becomes a must-have features. With Hieroglyphic Language( Chinese, Japanese..), the set of characters may reach 2000 to 3000 which is impossible to fit in one 2048×2048 texture. This tutorial aims to minimize total characters set when support new language and reduce time consumed each time your game’s text content expands.
What is “Font”?
A computer font (or font) is implemented as a digital data file containing a set of graphically related glyphs, characters, or symbols. – Wikipedia-
There are 3 types of computer font(Bitmap Fonts, Vector Fonts and Stroke Fonts). TextMesh Pro use Bitmap Fonts to store font data. Bitmap Fonts is the fastest and easiest way to render glyphs in computer graphic.
Why did I choose TextMesh Pro?
The render technique behind TextMesh Pro.
Text Mesh Pro use Signed Distance Fields thus enable it to render character more cleanly compare to default Unity Text.
This article describes in details the SDF technique used in Half- Life 2 and Team Fortress 2 which is implemented by Text Mesh Pro for Unity.
Text Mesh Pro Anatomy.
Text Mesh Pro generates its own font data from origin TTF font. The generated font data hold default font material, a texture contains all characters and other font settings such as scale, base line..
Somethings you must know about TextMesh Pro Font Asset.
Create a Text Mesh Pro Font Asset.
The TextMesh Pro font creation window can be opened in the editor via Window / TextMeshPro – Font Asset Creator.
Font Source is the font asset(tff, otf format ) which is used to generate the TextMesh Pro Font Asset.
Font Size is the point size of font to generate Font Asset’s Texture. I often leave it “Auto Sizing”.
Font Padding is the the padding between font characters in the font’s atlas. Padding creates room for SDF gradient thus make transition smoother and larger effect such as thick outline, shadow, glow.. I often use padding 4 or 5 pixels as the starting point and increase or decrease it until the effect looks good.
Atlas Resolution is the resolution of the Font Asset’s Texture. Bigger resolution produces better quality at the cost of atlas’s size.
Character Set is the set of characters which are included in font assets. TextMesh Pro supports predefine set like ASCII, ASCII extend.. or you can specify character range using decimal, hexadecimal and list of characters. You can reuse character set by create a text asset(a text file) and build your font from it.
Face info.
The basline is the horizontal line on which characters sit.
The ascender describes how far above the baseline characters can extend, which also defines the top of a line.
The descender does the same, but below the baseline.
The line height defines the distance between the tops of consecutive lines. If it is larger than the size of the ascender and descender combined, there will be a gap between lines. If it is smaller, then characters from different lines could overlap.
Underline dictates where underlines will be placed, relative to the baseline.
The superscript and subscript offsets are used to adjust the baseline for superscript and subscript text. Their size is a factor that is used to scale such text, relative to the normal font size.
The “Fallback Fonts Section” will hold reference to fallback font in case of the origin font missing a character. I often use it to support languages localization.
For more information, please visit this article and have a closer look at Text Mesh anatomy.
TextMesh Pro versus Default Unity Text
Text Mesh Pro renders glyphs much better than Unity Text.
TextMesh Pro is easier to handle text effect such as shadow, outline and we can use custom shader to create unique effect.
TextMesh Pro is superior to Unity Text in render glyphs cost and Garbage Collection when change text at runtime.
TextMesh Pro supports multi language much better than Unity Text due to “Fallback Mechanic”.
The only down side of Text Mesh Pro is the manual Font Asset Creator process which requires us to rebuild font assets each time we update game content.
Extended Latin Alphabet.
We often begin our game with English as default language. Luckily, most language uses Latin Alphabet like English with some specific character such as “â, ă, ơ..” We can build English Font assets as the default font, then set all other language as “Fallback Font”. When a character can not be found in the origin Font Asset, Text Mesh Pro will begin search in sub-sequence fallback font. This is the simplest way to handle language localization with TextMesh Pro but it must store all fallback font atlases in memory thus impact ram usage and GPU draw-call when renders glyphs from different atlas. Let’s call it Simple Localization Workflow.
There is another way of implement language localization with Text Mesh Pro which requires a little bit of code to eliminate the memory impact. In this approach, we use the English Font asset as the fall-back font for other language and a script to set the “Font Asset” property with the selected language in Text Mesh Pro component. Using this approach, we only load 2 atlases in memory for language localization thus reduce the memory consumption of font fallback mechanic. Let’s call it Better Localization Workflow.
Hieroglyphic Language( Chinese, Japanese, Korean..).
Chinese, Japan, Korean and other Hieroglyphic Language have a massive set of characters. To contain all the characters of each one, several atlases must be built(most platforms have 2048*2048 limit for texture size). A smarter solution is only used characters will be built into atlas thus dramatically reduce the atlas size. Japanese and Chinese share common set of characters which can be built to a common fall-back font to further reduce the atlas size of them.
What if your game allows user to interact with an Input Field, your TMP Font Asset have to contain all possible characters of the input language which is impossible for Hieroglyphic Language. For this use case, a Dynamic TMP Font Asset must be create to handle runtime-generate atlas. This type of TMP Font Asset shouldn’t be used in normal text field because it will trigger atlas rebuild each time a character is missing. This rebuild process will cause a lot Garbage Collection which decrease our game performance. Let’s call it Dynamic Localization Workflow.

Dynamic Localization Workflow Example.
First you will need no change the TMP Font Asset from static to dynamic, make sure the source font is not missing.
Then assign it to the text asset of the input field. Note that, source font must contain all needed characters in order to generate runtime TMP Font Asset properly.
Better Localization Workflow Example.
In my project, I often use Lean Localization to handle localization in game. It have a helper script called “LeanLocalizedTextMeshProUGUIFont.cs” for hot swap TMP Font Asset at runtime using a pre-config Lean Phrase.
First add a Lean Phrase which hold reference to our TMP font asset.
Then add a LeanLocalizedTextMeshProUGUIFont component to each TMP Text and config them with the “TMP_font_asset” Lean Phrase.
Preprocess Text Asset for TextMesh Pro Font Creator.
You can install thanh-nguyen-kim/character_processor (github.com) as UPM package or clone it then copy to your project. It contains a helper script to help processing our game text assets.
If you install the package using UPM, SampleScene.unity is read-only thus it can’t be opened. Drag SampleScene.unity into your project then you can open it as normal.
Remove duplicate characters(Optional).
Drag your text asset into the “Origin Text” property field.
Leave “Blueprint Texts” property field blank.
Press Play and the xxx_output.txt should appear in Streaming Assets folder.
Remove duplicate characters between language character sets.
Drag your text asset into the “Origin Text” property field.
Drag Blueprint Text assets into “Blueprint Texts” property field. You can have more than one blueprint.
Press Play and the xxx_output.txt should appear in Streaming Assets folder.
The left side is the Vietnamese character set without stripping characters already included in English character set
The right side is the Vietnamese character set after stripping characters already included in English character set.
We save a lot of Vietnamese Atlas size after stripping step thus reduce the build size of our game.
The Latin Alphabet base language, simple Chinese and Japanese share a large amount of common characters, remove the duplicate ones with this step can reduce the atlas size by half.
