How a pipeline gets here, and how to publish yours
Results are labelled by evidence. Measured by RTK: our CI. Author's benchmark: an A/B run the author published. Author's own usage: what their rtk counted on their traffic. Only a benchmark measures total cost; usage numbers measure output size, how much smaller tool outputs got.
- Run rtk pipeline share publish and choose GitHub repository. rtk creates the public repo in your account with your pipeline.toml, the rtk-pipeline topic and a README card carrying your own usage numbers. That is all it takes.
- Optional: to show a benchmark, add a benchmark.toml to that repo with the cost per trial with and without your pipeline, an optional quality metric, per task. Format.
- Within six hours a bot pre-checks the new commit with the standard rtk binary and opens a review in rtk-ai/pipelines.
- An RTK maintainer reads it and merges. Only merged versions appear here, pinned to that commit.
- Stars on your repo are the votes. Forks are remixes. Each pipeline has a discussion thread and a report link.
