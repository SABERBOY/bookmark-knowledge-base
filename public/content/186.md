Tri Inspector 2.0 is a significant milestone — rebuilt from the ground up on Unity's UI Toolkit, bringing a modern foundation, polished visuals, and long-requested features.
- 🎯 Unity 6 and above — minimum supported version is now Unity 6, allowing the project to adopt modern editor APIs without legacy baggage.
- 🖼️ UI Toolkit based — the entire rendering pipeline has been rewritten using UI Toolkit, replacing the old IMGUI backend.
- 📦 Prefab workflow support — Tri Inspector fully respects Unity's prefab override system, so modified properties are highlighted, revertable, and apply correctly across prefab instances and variants.
- ✨ New styles for UI elements — lists, groups, info boxes now have polished, consistent visual styles that not only integrate with Unity 6's editor theme, but redefine what an editor inspector can look like.
- 🛠️ Overall improvements and bug fixes — a wide range of edge-case bugs have been resolved and internal systems have been hardened, resulting in a more stable and predictable inspector experience.
- ↕️ TableList is now reorderable — rows in[TableList] can be dragged and reordered directly in the inspector, making list management significantly faster.
- 📖 Dictionary support — dictionaries can now be displayed and edited in the inspector across all supported Unity versions. Starting from Unity 6.6, dictionaries are also fully serializable by Unity itself.
- 🔍 Tri Project Validator — a brand-new validation window that runs every Tri attribute across your whole project, keeping it valid as you work and in CI. See Tri Project Validator below.
The same validation attributes that power the inspector now drive a dedicated Tri Validator window that checks your whole project. Open it from Tools/Tri Inspector/Validator.
- ✅ Keep your project valid — all issues are collected into one navigable tree so you can find and fix them before they ship.
- 🗂️ Validate the entire project — scan all assets and scenes in one pass, with configurable scope.
- ⚡ Live validation while you work — results stay current in the background as you edit, no manual rescan needed.
- 🌳 Hierarchy integration — on Unity 6.6+, validation hooks into the new Hierarchy window as dedicated error and warning columns, showing per-GameObject issue counts right where you work (while the Tri Validator window is open).
- 🤖 CI/CD and Agents ready — run a headless validation from code via TriValidator.ValidateProjectAsJson() to fail the build when issues slip in. When Unity Pipeline is installed, validation is also exposed as Pipeline CLI commands, so an AI agent can run it and act on the JSON report:
  - unity command tri validate_project — validate every in-scope asset and scene
  - unity command tri validate_scenes — validate the currently open scenes
  - unity command tri validate_asset --global_id <id> — validate a single asset by its globalId
TriInspector ships with a built-in Samples Window — your interactive playground for every attribute in the package. Open it from Tools/Tri Inspector/Samples and browse all attributes organized by category. Select any sample to instantly see a live inspector with real fields, so you can explore exactly how each attribute looks and behaves without writing a single line of code.
Each sample also displays its full source code right in the window, so you can see exactly how the attribute is used and copy it straight into your project. It's the fastest way to discover what TriInspector can do and understand how to apply it.

Properties can be grouped in the inspector using the [Group] attribute. TriInspector supports six group types, each declared on the class with a corresponding [Declare*Group] attribute:
- BoxGroup — wraps properties in a titled or untitled box
- FoldoutGroup — collapses properties behind a foldout toggle
- ToggleGroup — a foldout with a built-in enable/disable toggle
- TabGroup — organises properties into named tabs, showing one at a time
- HorizontalGroup — lays properties out side by side in a row
- VerticalGroup — stacks properties vertically, typically nested inside a horizontal group
Groups can be freely nested and combined to build complex, multi-region inspector layouts.
Tri Inspector uses a unified extensibility model — the same validators, drawers and processors that power the built-in attributes are available to you. Everything shipped in the package is written against the same base classes you extend, so your extensions work everywhere, including the Tri Project Validator. Each extension is a class marked with a registration attribute and discovered automatically.
Validation is a shared pipeline you can plug into at two levels:
- TriValueValidator<T> — validate every property of a given type T. Register with [RegisterTriValueValidator].
- TriAttributeValidator<TAttribute> — validate properties marked with your own attribute TAttribute. Register with [RegisterTriAttributeValidator].
[RegisterTriAttributeValidator]
public class NotEmptyValidator : TriAttributeValidator<NotEmptyAttribute>
{
    public override TriValidationResult Validate(TriProperty property)
    {
        if (string.IsNullOrEmpty(property.Value as string))
            return TriValidationResult.Error($"{property.DisplayName} must not be empty");
        return TriValidationResult.Valid;
    }
}
Every result you return appears both inline in the inspector and in the project-wide Tri Validator window.
You can control how a property is rendered at two levels:
- TriValueDrawer<T> — draw every property of type T. Use this to provide a custom UI Toolkit element for your own serializable types.
- TriAttributeDrawer<TAttribute> — draw or decorate properties marked with your attribute TAttribute, with typed access to the attribute via Attribute. Use TriDrawerOrder to control whether your drawer replaces the field, decorates it, or wraps the whole inspector element.
[RegisterTriAttributeDrawer(TriDrawerOrder.Drawer)]
public class MyAttributeDrawer : TriAttributeDrawer<MyAttribute>
{
    public override VisualElement CreateVisualElement(TriProperty property, VisualElement next)
    {
        // return your own UI Toolkit VisualElement
    }
}
Register value drawers with [RegisterTriValueDrawer] and attribute drawers with [RegisterTriAttributeDrawer].
For the most advanced cases, TriTypeProcessor operates at the structural level, before any drawing happens. A processor receives a type and the list of TriPropertyDefinitions being built for it, so you can add, remove, reorder or inject properties. This is the same mechanism Tri Inspector uses internally to gather fields, properties and buttons. Register with [RegisterTriTypeProcessor(order)], where order controls when your processor runs relative to the built-in ones.
[RegisterTriTypeProcessor(10000)]
public class MyTypeProcessor : TriTypeProcessor
{
    public override void ProcessType(Type type, List<TriPropertyDefinition> properties)
    {
        // inspect and modify the property definitions for `type`
    }
}
